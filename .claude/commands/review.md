# /review - コードレビュー

現在の変更差分をレビューし、改善点やフィードバックを提供する。

## 手順

1. **変更状況を確認**
   ```bash
   git status
   git diff
   git diff --staged
   git log origin/$(git branch --show-current)..HEAD --oneline
   ```

2. **変更内容を分析**
   - 変更されたファイルを読んで内容を理解
   - 以下の観点でレビュー

## レビュー観点

### コード品質
- [ ] 型安全性: 適切な型定義がされているか
- [ ] エラーハンドリング: 適切にエラーを処理しているか。特に境界（外部 API 呼び出し、DB、拡張の 6MB 制約）
- [ ] 命名: 変数名・関数名は分かりやすいか。日本語コメントは意図が明確か
- [ ] 重複: 不要な重複コードはないか
- [ ] 複雑さ: 過度に複雑な実装になっていないか

### セキュリティ
- [ ] 認証・認可: `authenticate()` の `requireRole` を適切に使っているか
- [ ] 権限チェック: 見守る側が自分の対象以外のデータにアクセスできる隙間がないか
- [ ] 機密情報: シークレットがハードコードされていないか。`.env.example` に変数名だけ書いてあるか
- [ ] SQL: Drizzle を経由しており、生 SQL に手入力パラメータを注入していないか

### 設計
- [ ] ADR-0001（生存検知の多層シグナル + 2 段階エスカレーション）と矛盾していないか
- [ ] フェイルセーフ原則: シグナル途絶＝通知側に倒す設計を維持しているか
- [ ] iOS 拡張: ネットワーク不可 / 6MB RAM の制約を守っているか
- [ ] シグナルは冪等キー `(watchedId, type, observedAt, deviceId)` を保っているか

### プロジェクト規約
- [ ] 絵文字を使用していない
- [ ] コメント・コミットメッセージが日本語
- [ ] `pnpm` を使用（`npm` / `npx` 禁止）
- [ ] Biome / TypeScript strict をパスしている

3. **フィードバックを報告**
   - 問題点があれば具体的に指摘
   - 改善案を提示
   - 良い点も伝える
