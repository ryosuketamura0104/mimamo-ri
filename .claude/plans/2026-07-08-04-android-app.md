# Plan 04: Androidアプリ

## Context

`android/` に Kotlin + Jetpack Compose アプリを構築。iOS（Plan 03）と同一のロール分岐・API・エスカレーションフローだが、
シグナル収集はAndroidの方が素直: `UsageStatsManager`/`UsageEvents` で画面ON・ロック解除・アプリ利用の**履歴そのもの**が取れる（ADR-0001）。

## 1. プロジェクト構成

- Gradle (Kotlin DSL) + Compose + minSdk 26目安（UsageStats・通知チャンネル安定圏）
- Firebase Auth + FCM
- モジュール: `app`（UI）、`core`（APIクライアント・シグナル収集。iOSのMimamoriKit相当）

## 2. シグナル収集

| シグナル | 実装 |
|---------|------|
| `usage_stats` | `UsageEvents` から `SCREEN_INTERACTIVE` / `KEYGUARD_HIDDEN` / アプリforeground イベントを取得し、observedAt付きでバッチ報告 |
| `steps` | `SensorManager` の歩数計 or Health Connect |
| `app_open` | 自アプリ起動時 |
| `checkin_tap` | 本人確認通知への応答 |

- 同期: WorkManager 定期ジョブ（15分〜1時間）+ FCM高優先度データメッセージでの補助起床（Doze対策）
- `PACKAGE_USAGE_STATS` は特別権限: オンボーディングで設定画面へ誘導（`Settings.ACTION_USAGE_ACCESS_SETTINGS`）
- 電池最適化除外の案内（`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）。メーカー独自キラー（Xiaomi等）向けの案内文も用意

## 3. UI

- オンボーディング: 通知許可（API 33+）→ 使用状況アクセス → 電池最適化除外 → ペアリング
- 見守られる側/見守る側の画面はPlan 03と同構成（一覧・アラート詳細・設定編集・メッセージ送信）
- Widget: Glance で天気/メッセージ表示 +「元気です」ボタン

## 4. 検証

- Dozeモード下でのWorkManager+FCM起床の実機確認（`adb shell dumpsys deviceidle` でDoze強制）
- 使用状況アクセスを剥奪された場合の検知とユーザー通知（設定が外れたら見守る側にも知らせる）

## 完了条件

- iOS版と同一のサーバーAPIで、シグナル報告→途絶→エスカレーションの一連が実機で通る
