# Plan 03: iOSアプリ本体 + 拡張群

## Context

`ios/` に Swift/SwiftUI アプリを構築。1つのアプリで見守る側/見守られる側の両ロールに対応（ログイン後のロールで画面分岐）。
ターゲット構成: App本体 + WidgetExtension + LocationPushExtension + NotificationServiceExtension + DeviceActivityMonitorExtension + AppIntents。
シグナル設計・各拡張の役割は ADR-0001 の表を正とする。Plan 02（スパイク）の結果を反映してから本実装に入ること。

## 1. プロジェクト構成

- Xcode プロジェクト。最低iOS 17（インタラクティブWidget・オートメーション「すぐに実行」前提）
- App Group `group.com.crouton.mimamori`（仮）で全拡張とデータ共有
- 共有コード（APIクライアント、シグナルキュー、保護ファイルプローブ）は内部SwiftPMパッケージ `MimamoriKit` に切り出し、全ターゲットから利用
- Firebase Auth SDK（メール+Google）。APIは Plan 01 の `/api/v1/`

## 2. MimamoriKit（共有基盤）

- **APIClient**: IDトークン付与、`POST /signals` バッチ送信
- **SignalQueue**: 拡張はネットワーク不可 or 時間制限があるため、シグナルは一旦App Groupのファイルに追記し、送信機会（本体起動時、LocationPush応答時、NSE実行時、BGAppRefresh）にまとめてPOST。observedAtを保持し冪等
- **LockStateProbe**: `FileProtectionComplete` ファイルの読み取り試行。ファイル初回作成は本体アプリの解除中に実施
- **PedometerReader**: CMPedometer で過去24hの歩数照会

## 3. 見守られる側フロー

- オンボーディング（許可取得の順序が重要、1画面1許可）:
  1. 通知許可 2. 位置情報「常に許可」（ロケーションプッシュ前提の説明画面を挟む） 3. FamilyControls承認+全カテゴリ選択 4. モーションアクセス（歩数） 5. オフロードOFF案内（設定手順の図解） 6. （任意）ショートカットオートメーション設定ガイド
- 招待コードの発行（watcher側から受けるか、watched側から発行してwatcherに渡す。Plan 01のinvitations API）
- ホーム: 直近シグナル状況の自己確認、設定同期状態
- 本人確認通知（confirming時）への応答: 通知タップ→アプリで「元気です」ボタン→`checkin_tap`シグナル

## 4. 拡張群

| 拡張 | 役割 |
|------|------|
| **WidgetExtension** | 天気 or 見守る側からのメッセージ表示（`GET /weather`, messages）。`getTimeline`内でLockStateProbe→SignalQueueに`widget_probe`記録。インタラクティブボタン「元気です」（AppIntentで即時報告） |
| **LocationPushExtension** | CLLocationPushServiceExtension。位置+LockStateProbe+SignalQueueの滞留分を応答時にまとめて送信。エンタイトルメント取得までは無効化してビルド可能に |
| **NotificationServiceExtension** | mutable-content通知受信時にSignalQueueをフラッシュ+`nse`シグナル送信 |
| **DeviceActivityMonitorExtension** | Plan 02の成果を移植。`eventDidReachThreshold`でApp Groupに`screen_time`記録 |
| **AppIntents** | 「生存報告」インテント（ショートカットオートメーション用、バックグラウンド実行可） |

- 本体は他に: BGAppRefreshTask でのキュー送信、`protectedDataDidBecomeAvailable` 在駐中の解除記録、アプリ起動時の`app_open`シグナル
- watch_settings同期: 起動時+プッシュ契機で取得し、DeviceActivityScheduleを`activityIntervalHours`で張り直す

## 5. 見守る側フロー

- 見守り対象一覧（最終シグナル・状態バッジ: 正常/確認中/アラート/端末オフライン）
- アラートプッシュ受信→詳細（最終シグナル時刻・最終位置の地図表示）→解消操作
- 設定編集（T、静穏時間帯、区間刻み）、Widgetメッセージ送信
- 課金画面はPlan 06で追加

## 6. 検証

- 実機で: オンボーディング全許可フロー、シグナルがサーバーのsignalsテーブルに届くこと、エスカレーションの本人確認通知→応答→解消の一連
